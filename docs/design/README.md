## 与实际实现的差异

| PRD / 原型 | 实际实现 | 原因 |
|---|---|---|
| Claude Haiku 做抽取、Whisper 做转写 | 任意 OpenAI 兼容网关；默认 kimi 做推理与视觉、qwen 做 ASR/TTS | 模型名全部是配置项，不绑定单一供应商 |
| 只有「录入 / 查询」两种意图 | 三分类前置路由 + function-calling 工具 agent 处理任意操作 | 见 `../DEVELOPMENT.md` |
| 免费额度 + 按用量买次数包 | 无限制使用，仅记录用量 | MVP 阶段先验证产品，不做支付 |
| 匿名设备登录 | 邮箱验证码登录（设备登录保留为兼容接口） | 换机不丢数据 |
| 语音仅服务端转写 | 浏览器 Web Speech 优先，服务端 ASR 兜底，再兜底手动输入 | 端侧实时、零成本；网关通道不可用时不影响使用 |
| 中文界面，中 / 英 / 西三语切换 | 默认英文，可切中文；西语未实现故不提供 | 面向英文用户主推；服务端生成的文案（箱名、确认摘要等）也随账号语言 |

## Overview

BoxMind 是一个面向 C 端普通消费者的"箱子里装了什么"管理应用。核心闭环：**创建箱子 →（语音 / 拍照 / 扫码）录入物品 → 自然语言提问找到物品**。设计原则：一屏、一个大按钮、零学习成本、无表单。

## About the Design Files

`prototype/` 里的文件是**用 HTML 制作的设计参考（design reference）**，展示预期的外观和交互行为，**不是生产代码**。实现时在目标技术栈中重新实现这些设计：

- 按 PRD §5：MVP 为 **PWA（React）**，一套代码覆盖 iOS/Android/Web。若仓库已有既定框架/组件库，遵循现有模式。
- 原型中所有"模拟"环节（预设语音脚本、假摄像头取景、定时器假装的 AI 延迟）都要替换为真实实现（见下文「原型模拟 → 真实实现对照表」）。
- 原型在 iPhone 设备框（`ios-frame.jsx`）内展示，设备框本身不需要实现。

## Fidelity

**High-fidelity（高保真）**。颜色、字号、间距、圆角、文案、交互均为最终设计意图，应按像素级还原（在 402×874 逻辑分辨率下设计，需做响应式适配）。唯一例外：箱子"照片"在原型里是牛皮纸色渐变占位图，真实实现中应显示用户拍摄的照片，无照片时可用此占位风格。

## Screens / Views

原型共 9 个界面（HTML 中均有 `data-screen-label` 标注）。布局细节请直接读原型源码（全部 inline style，所见即所得），此处描述结构与行为：

### 1. 新手引导（3 屏）
跳过按钮右上。每屏：视觉演示 + 步骤标签胶囊 + 28px 标题 + 15px 说明 + 进度点 + 渐变主按钮（最后一屏文案"开始使用"）。三屏内容：① 马克笔写编号即可开始 ② 按住说话 AI 全记住 ③ 问一句就找到。

### 2. 主界面（核心，"一屏一个大按钮"）
- 顶部：品牌字 BoxMind（渐变文字）+ 统计行"N 个箱子 · M 类物品已记住"；右上"剩 N 次"额度胶囊（点击进设置）
- 提示卡：未录入过时显示马克笔教学卡；录入后变为绿色活动卡（最近一次入库摘要，可点进箱子）
- 中部：**150px 渐变圆形麦克风按钮**（外圈两层呼吸光环），下方"按住说话"+ 动态提示文字
- 底部输入行（flex, gap 10px）：文字输入胶囊（点击进问答）+ 52px 相机按钮（拍照识别）+ 52px 扫码按钮
- 提问示例芯片 2 枚；底部 Tab 栏（首页/箱子/我的，毛玻璃）

### 3. 语音录入浮层（覆盖全屏，毛玻璃深底）
五个阶段：
1. **recording**：红点"正在听…"胶囊 + 7 根渐变波形条（scaleY 动画）+ 转写文字逐字出现（带光标）+ 底部"松开手指结束"
2. **parsing**：原话置灰显示 + 渐变 sparkle"AI 正在整理…"+ 三点跳动
3. **confirm**（说了箱号时）：结构化确认卡 — 箱子徽章 + "新箱子 · 自动创建"绿字 + 物品行（名称/数量）+ 位置行 + "GPS 已记录"标签 + 原话引用；按钮「修正」（进编辑态 textarea，可改后重新解析）/「确认入库」
4. **askbox**（没说箱号时，关键兜底流程）："已整理 3 类物品 — 放进哪个箱子？" + 物品卡 + 选项列表：**琥珀色虚线"新建 N号箱"（自动取最大数字编号+1，标"推荐"）** + 最近 3 个箱子；点选即入库
5. **done**：绿色大对勾 + 标题/摘要两行；若新建了箱子，显示琥珀色横幅 **"记得用马克笔把「N」写到箱子上"**；按钮「查看箱子」/「完成」

### 4. AI 问答（对话界面)
- 用户气泡右对齐 #273048；AI 消息左侧渐变 sparkle 头像 + 卡片气泡，**打字机逐字输出**（带光标），完成后下方淡入**可点击的箱子卡片**（缩略徽章 + 名称 + 位置 + 距离 + chevron，点击进箱子详情）
- 思考中：三点跳动气泡。底部：问题芯片（已问过的消失）+ 假输入框 + 渐变小麦克风（同样支持按住说话）

### 5. 拍照识别
- 取景：模拟俯拍打开的箱子（内含物品、箱角手写"2号"）、三分构图线、白色双圈快门
- 拍下后：扫描线 + "AI 识别中…"约 2s
- 结果底浮层：「识别结果」+ 重拍；目标箱卡片"入库到 2号箱 · 自动新建（照片上识别到手写编号「2号」· 照片将存为封面）"；物品行 ×4，每行勾选圆点 + 数量 + 置信度标签（高=绿/中=琥珀），点行切换勾选；主按钮"确认入库（N 类）"实时计数

### 6. 扫码
- 取景 + 236px 四角取景框 + 往返扫描线；约 2.4s 后识别成功：绿色边框闪现 + 底浮层（"识别成功 · BX-A2-0214"绿胶囊 + 箱子卡片 + 「录入到此箱」/「查看箱子」+ 重新扫描）
- 底部链接"箱子没贴码？输入手写编号"→ 输入浮层（提示数字/字母/中文均可），已存在则打开详情，不存在则即时建箱

### 7. 箱子列表
28px 标题 + 计数；两列网格卡片：牛皮纸渐变封面（胶带条 + 旋转手写编号 + "新"徽章）+ 名称 + 位置行（pin 图标）+ "N 类物品 · 更新时间"；末尾虚线"+ 写个编号 开口即建"卡

### 8. 箱子详情
240px 封面（渐变占位，注明"箱子照片 · 占位"）+ 返回；标题 + 徽章行（琥珀"手写编号 N"/ 蓝"QR·码值"/ 灰"更新于…"）；位置卡：**CSS 网格模拟小地图**（脉冲 pin + 距离胶囊）+ 位置描述 + "GPS 已记录，仅自己可见"；物品清单卡（名称 + 数量，空箱显示虚线引导）；语音来源标注；渐变主按钮"录入到此箱"（回主页并显示目标箱芯片）

### 9. 设置（"我的"）
额度卡（剩余次数大数字 + 进度条 + "购买次数包"按钮）；语言三选（中文/English/Español，选中高亮）+ "AI 对话语言自动识别"说明；GPS 开关（渐变轨道）；列表卡（导出数据 JSON/CSV、语音识别、关于）；底部隐私文案。次数包浮层：入门 $0.99/200 次、标准 $2.99/800 次（高亮"最多人选"）、大容量 $6.99/2500 次、无限订阅 $1.99/月

## 原型模拟 → 真实实现对照表

| 原型中的模拟 | 真实实现（按 PRD §5） |
|---|---|
| 预设语音脚本逐字打出 | MediaRecorder 录音 → 后端 → Whisper API 转写，转写结果展示给用户确认 |
| 定时器 1.5s 后出确认卡 | Claude API（Haiku）意图识别 + 信息抽取，强约束 JSON 输出：{箱号?, 物品[{名称,数量}], 位置?} |
| 没说箱号 → 写死的追问界面 | 抽取结果缺 box 字段时触发同样的追问 UI；"新建 N号箱"编号 = 该用户最大数字编号+1；归一化"1号"="1号箱"="Box 1" |
| 问答的预设 Q&A + 打字机 | RAG：物品 embedding 入库（pgvector），检索后 Claude 生成回答；流式输出对应打字机效果；回答中引用的箱子渲染为可点卡片 |
| 假摄像头 + 写死识别结果 | 扫码：摄像头 + ZXing/jsQR（QR + EAN/UPC/Code128）；拍照识别：图片传 Claude 视觉模型，返回物品清单 + 置信度 + OCR 手写编号 |
| 牛皮纸渐变"照片" | 真实照片存储（压缩后上传），列表/详情/卡片用作封面 |
| 用量 used 计数 +1 | usage_log 计量：录入 1 次、AI 查询 1 次；扫码/浏览免费；额度用尽引导购买 |
| GPS 文案写死 | Geolocation API，拒绝授权全功能降级（PRD 验收标准） |

## State Management（原型已验证的状态机）

- `screen`: onboarding | home | ask | scan | camera | boxes | boxdetail | settings
- 语音 `recPhase`: idle → recording → parsing → (confirm | askbox) → done；confirm 可进 edit 再 reparse
- 拍照 `camPhase`: live → recog → result；扫码 `scanPhase`: scanning → found
- 数据：`boxes[{id, label(用户编号), name, code?, locText?, gps?, photo?, items[{n,q}], updated}]`——**用户编号 label 必有**（四条创建路径收口 + 追问 + 自动起号），条码/二维码是同一箱子的别名
- 录入/提问成功后 `used+1`；所有列表与统计由 boxes 派生
