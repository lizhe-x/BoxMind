# BoxMind — AI 智能仓储助手
## 产品需求文档（PRD）v1.0

> 一句话定位：扫一下箱子，说一句话，AI 帮你记住一切。
>
> Scan a box, say a word, AI remembers everything.

- 文档版本：v1.0
- 日期：2026-06-11
- 状态：Draft
- 产品代号：BoxMind（暂定名）

---

## 1. 背景与机会

### 1.1 用户痛点

- 人们把东西装箱存进仓库/车库/储物间后，很快忘记存了什么、放在哪里
- 现有库存类 App（Everspruce、Storage Box Organizer、QR Inventory 等）依赖"拍照 + 手动填表"，录入成本高，普通用户难以坚持
- 市面上没有任何面向 C 端、支持中文、以 AI 对话为核心交互的产品

### 1.2 市场空白

| 维度 | 现有竞品 | BoxMind |
|------|---------|---------|
| 目标用户 | 企业 / 重度整理者 | 普通消费者 |
| 核心交互 | 表单填写 | 语音 / 自然语言 |
| 查询方式 | 关键词搜索 | AI 对话问答 |
| 中文支持 | 无 | 原生支持 |
| 多语言 | 个别支持欧语 | 中 / 英 / 西 |

### 1.3 商业判断

- 低频但高留存：用户数据沉淀形成强锁定（数据即留存）
- 负流失率特征：存量用户持续累积
- C 端验证后可向 B 端（仓储公司白标 SaaS）扩展

## 2. 产品目标

### 2.1 MVP 目标（第一阶段）

- 验证核心假设：用户愿意用"扫码 + 说话"的方式记录物品
- 跑通核心闭环：创建箱子 → 录入物品 → AI 查询找到物品
- 获取首批种子用户（目标：500–1000 注册用户）

### 2.2 非目标（明确不做）

- 不做照片识别物品（第二阶段）
- 不做多人协作 / 家庭共享（第二阶段）
- 不做 B 端管理后台（第三阶段）
- 不做原生 App（MVP 用 PWA / Web App 验证）

---

## 3. 目标用户

### 3.1 核心画像

1. **搬家人群**：短期密集使用，录入需求强烈
2. **仓储租户**：长期存放，遗忘问题最严重
3. **华人家庭**：语言壁垒使其无法使用现有英文产品，微信群传播获客成本低
4. **整理收纳爱好者**：家庭储物间、车库、阁楼场景

### 3.2 首发市场

- 美国华人社区（Orlando / Tampa 起步，微信群 + 小红书冷启动）
- 英语用户（Reddit r/moving、r/organization）
- 西语用户（第二波扩展）

## 4. 功能需求

### 4.1 多语言支持 【P0】

- 首发支持：简体中文、English、Español
- 界面语言可手动切换，默认跟随系统语言
- AI 交互语言自动识别：用户说中文 AI 答中文，说英文答英文（无需手动设置）
- 物品数据跨语言可查：中文录入的物品，用英文提问也能查到（依赖 AI 语义理解，非关键词匹配）

### 4.2 极简输入界面 【P0】

设计原则：**一屏、一个大按钮、零学习成本**

- 主界面只保留三个动作入口：
  - 🎤 按住说话（语音录入 / 语音提问）
  - ⌨️ 文字输入框（录入 / 提问共用一个入口，AI 自动判断意图)
  - 📷 扫码按钮
- 无表单、无必填字段、无分类树
- 用户说什么 / 输什么，AI 自动解析出：物品名称、数量、所属箱子、位置等结构化信息

示例交互：

```
用户（语音）："1号箱我放了冬天的羽绒服三件、雪地靴两双，还有电热毯"
AI：✅ 已记录到 1号箱：
    · 羽绒服 ×3
    · 雪地靴 ×2
    · 电热毯 ×1

用户（文字）："我的雪地靴在哪？"
AI：在 1号箱 🏠 车库左侧货架（2026-06-11 录入）
```

### 4.3 语音识别 【P0】

- 全部语音处理通过 AI API 完成（Whisper 或同级 STT），客户端不做本地识别
- 支持中 / 英 / 西三语自动识别，含中英混说场景
- 录音 → 转文字 → AI 解析意图 → 结构化入库，全链路对用户透明
- 转写结果展示给用户确认（可一键修正），避免错误入库

### 4.4 箱子管理 【P0】

箱子是核心数据单元。设计原则：**一支马克笔就能开始用，扫码不是前提**。

支持三种定义方式（任选其一或组合）：

1. **手写编号 / 名字（零门槛，主推方式）**：用户用马克笔直接在箱子上写 "3号"、"ABC"、"厨房杂物" 等任意编号或名字（中英文均可），然后在 App 里说出或输入同样的编号/名字即可创建并录入。无需任何标签、贴纸或打印设备。
   - 示例："3号箱放了锅碗瓢盆" → 自动创建 3号箱并录入
   - 编号格式完全自由：数字（3号）、字母（Box A）、中文（红色大箱）、混合（A2杂物）均可
2. **扫码绑定（可选增强）**：扫描二维码或条形码，将码与箱子绑定（可用现成快递箱条码、自购二维码贴纸，或 App 内生成打印）。已有手写编号的箱子也可以后补绑定码，两个入口指向同一个箱子
3. **箱子拍照（MVP 包含，仅存档不识别）**：创建或编辑箱子时可拍一张外观照片，帮助用户肉眼辨认（"哦，是那个红色的箱子"）。本期只存图展示，**不做图像识别**（视觉识别物品归入第二阶段）

行为规则：

- 录入物品时如提及未创建的箱子，自动创建（如用户说 "5号箱放了……"，5号箱不存在则即时创建）
- 一个箱子可同时拥有编号、名字和绑定的码，三者均可作为查询入口
- 箱子可编辑、合并、清空、删除（删除需二次确认）

### 4.5 扫码功能 【P0】

两个方向的扫码动作：

- **扫码查询**：扫箱子上的码 → 立即展示该箱所有物品清单 + 位置信息
- **扫码录入**：扫码后直接进入该箱的录入模式（语音或文字），说的内容自动归入此箱

技术要求：

- 支持 QR Code 与主流一维条形码（EAN/UPC/Code128）
- 使用手机摄像头，Web 端基于 WebRTC + 解码库实现（MVP 不依赖原生能力）

### 4.6 箱子位置记录 【P0】

两层位置信息，互为补充：

1. **文字位置（用户描述）**：语音或文字录入，如 "车库左侧第二层货架"、"CubeSmart 单元 #214"
   - 位置描述可被 AI 查询理解（"车库里有哪些箱子？"）
2. **GPS 定位（自动）**：录入 / 更新箱子时自动记录当前 GPS 坐标
   - 用途：区分 家里 / 仓库 / 父母家 等不同存放地点
   - 查询时可返回地图位置（"3号箱在 Davenport 的仓库，距你 1.2km"）
   - 隐私：GPS 为可选授权，拒绝授权不影响其他功能；坐标仅用户本人可见

### 4.7 AI 查询 【P0】

核心能力，全部通过 AI API（Claude）实现：

- 自然语言问答："我的圣诞装饰在哪？"、"3号箱里有什么？"、"上个月存的电子产品有哪些？"
- 语义检索：基于 RAG（向量检索）而非关键词匹配，"保暖的衣服" 能匹配到 "羽绒服"
- 跨语言查询：中文录入英文查询互通
- 聚合问答："我一共有几个箱子？"、"哪个箱子还没记录位置？"

### 4.8 账号与数据 【P0】

- 注册方式：邮箱 / Google / 微信（按市场优先级排）
- 数据归属用户本人，支持导出（JSON / CSV）
- 免费额度 + 按用量付费（详见第 6 节）

### 4.9 第二阶段功能 【P1，本期不做】

- 拍照识别物品（视觉识别，照片存档已在 MVP 实现）
- 家庭 / 团队共享箱子
- 物品提醒（"冬衣已存 8 个月"）
- NFC 标签支持
- 原生 iOS / Android App
- B 端管理后台（仓储公司白标）

## 5. 技术方案

### 5.1 架构总览

```
客户端：PWA（React）— 一套代码覆盖 iOS/Android/Web
   │
   ├─ 语音：MediaRecorder 录音 → 后端 → Whisper API
   ├─ 扫码：摄像头 + ZXing/jsQR 解码
   └─ GPS：浏览器 Geolocation API
   │
后端：Node.js / Python（FastAPI）
   │
   ├─ AI 层：Claude API
   │    ├─ 意图识别（录入 vs 查询）
   │    ├─ 信息抽取（物品/数量/箱子/位置 → 结构化 JSON）
   │    └─ 问答生成（RAG 检索结果 → 自然语言回答）
   │
   ├─ 检索层：向量数据库（pgvector / Pinecone）
   │    └─ 每条物品记录 embedding 入库
   │
   └─ 数据层：PostgreSQL
        ├─ users / boxes / items / locations
        └─ usage_log（计量计费）
```

### 5.2 核心数据模型

```sql
users(id, email, lang, created_at, credit_balance)

boxes(id, user_id, number, name, barcode, photo_url,
      location_text, gps_lat, gps_lng, updated_at)

items(id, box_id, name, quantity, note,
      embedding vector, created_at)

usage_log(id, user_id, action_type, tokens_used, created_at)
```

### 5.3 AI 调用设计

| 场景 | 模型 | 预估单次成本 |
|------|------|------------|
| 语音转文字 | Whisper | ~$0.001/条 |
| 意图识别 + 信息抽取 | Claude Haiku | ~$0.0003 |
| RAG 问答 | Claude Haiku | ~$0.0006 |
| 复杂聚合查询 | Claude Sonnet | ~$0.003 |

成本控制策略：

- 默认走 Haiku，仅复杂查询升级 Sonnet
- 信息抽取使用强约束 JSON 输出，控制输出 token
- 活跃用户月均 AI 成本控制在 $0.05–0.15

### 5.4 性能与可用性要求

- 语音录入端到端（松开按钮 → 显示结果）< 3 秒
- AI 查询响应 < 2 秒
- 扫码识别 < 1 秒
- 离线降级：无网络时可查看本地缓存的箱子清单（只读）

## 6. 商业模式

### 6.1 定价：免费额度 + 按用量买包

定价原则：不向用户暴露 "token" 概念，统一计为 "操作次数"。

| 计费动作 | 消耗 |
|---------|------|
| 录入一条（语音或文字） | 1 次 |
| AI 查询一次 | 1 次 |
| 扫码查看箱子 | 免费 |
| 浏览已有记录 | 免费 |

| 产品 | 价格 | 包含 | 成本 | 毛利率 |
|------|------|------|------|-------|
| 新用户赠送 | $0 | 50 次 | ~$0.05 | — |
| 入门包 | $0.99 | 200 次 | ~$0.20 | ~80% |
| 标准包 | $2.99 | 800 次 | ~$0.60 | ~80% |
| 大容量包 | $6.99 | 2500 次 | ~$1.50 | ~79% |
| 无限订阅（重度用户可选） | $1.99/月 | 无限 | 浮动 | — |

### 6.2 阶段目标

```
阶段一（0 → 1 万用户）：免费跑量，验证产品，不追求收入
阶段二（1 万 → 5 万）：上线付费包，验证付费率与复购
阶段三（5 万+）：以真实用户数据为筹码，启动 B 端
   ├─ 仓储公司白标 SaaS（$300–800/月/门店）
   ├─ 搬家公司合作
   └─ 保险公司数据合作（家财险清单场景）
```

### 6.3 冷启动渠道

- 华人微信群（Orlando / Tampa）— 第一批种子用户
- 小红书："美国搬家必备神器" 类内容
- Reddit：r/moving、r/organization、r/declutter
- 西语社区（第二波）

## 7. MVP 排期（3 周）

| 周 | 交付内容 |
|----|---------|
| 第 1 周 | Web App 框架、账号系统、箱子/物品 CRUD、文字录入 + AI 抽取、AI 查询（RAG） |
| 第 2 周 | 扫码绑定/查询/录入、箱子拍照存档、GPS 位置记录、中英西三语界面 |
| 第 3 周 | 语音录入（Whisper 链路）、用量计费系统、免费额度、上线部署 |

### 验收标准（MVP Definition of Done）

- [ ] 新用户 60 秒内完成：创建箱子 → 语音录入 3 件物品 → 提问并得到正确答案
- [ ] 中文录入、英文查询，结果正确
- [ ] 扫码后 1 秒内显示箱内清单
- [ ] GPS 授权拒绝时全部功能正常降级
- [ ] 用量计数准确，免费额度用尽后正确引导购买

## 8. 关键指标（北极星 + 辅助）

- **北极星指标：周录入物品总数**（衡量真实使用而非注册虚荣指标）
- 注册 → 首次录入转化率（目标 > 60%）
- 30 日留存（目标 > 25%，数据锁定效应下应显著高于工具类均值）
- 免费额度耗尽 → 付费转化率（阶段二目标 > 8%）
- 单用户平均箱子数 / 物品数（数据沉淀深度）

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| AI 抽取错误导致脏数据 | 录入结果即时展示 + 一键修正；低置信度时主动追问 |
| 语音识别中英混说出错 | Whisper 多语模式 + 转写确认环节 |
| 用户隐私顾虑（GPS / 物品清单） | GPS 可选授权；数据加密存储；明示数据归属用户、可随时导出删除 |
| 低频导致付费意愿弱 | 按用量付费匹配低频行为；数据沉淀提高迁移成本 |
| 大厂 / 竞品跟进 | 抢占华人垂直市场 + 数据锁定先发优势；快速向 B 端渗透建立渠道壁垒 |
